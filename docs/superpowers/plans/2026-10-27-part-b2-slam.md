> **Time:** one task at a time.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** never debug SLAM by hand again. After any run with SLAM, one command (or `map_course` itself) says:
- which odometry it used;
- how far each source drifted;
- every correction and loop closure, sized at the car;
- per-lap closure numbers;
- map consistency;
- why scans were dropped.

A replay can then recreate the run exactly.

**Architecture:**
- **Recording** is `race_diagnostics`' `record_run.py`, which bringup's `auto_record` and `map_course` both use.
- **Analysis** builds on Part A's ROS-free `tools/run_analysis/slam_metrics.py`, `slam_bag.py` and `slam_replay.py`.

**Tech stack:** Python 3.12, ROS 2 Jazzy, `rosbag2_py`, slam_toolbox (apt), numpy and scipy, pytest.

**Starting point:** branch `slam-gapfollow-part-a`, merged or branched from.

## Global Constraints

- **Analysis never costs the car CPU while it drives or maps.** Analysis happens after the run. The only additions during a run are `tegrastats` and a 1 Hz `/proc` sampler.
- **Recorders only read.** They subscribe, read `/proc`, and call parameter services. They never publish a drive topic, and never write inside an existing run folder except `analysis/`.
- **Replays run isolated.** `slam_replay.py` keeps its isolation (domain 77, localhost) and its refusal beside `vesc_driver_node`, `urg_node` or `joy`.
- **Test rules:** Hard rules 1-2, and an oracle for every expected value (`TEST_QUALITY_STANDARDS.md`). `race_diagnostics` tests run sourced and isolated.
  - Known flaky test, from `main`: `test_auto_record_node.py::test_records_while_an_algorithm_runs_and_closes_the_bag_when_it_goes` fails under parallel load and passes alone. Don't "fix" it by loosening; if it blocks, report it.
- **Docs** follow the `novice-docs` skill.

## Review Focus

1. **A node that starts minutes after the recorder** (SLAM started after `gap_follow` in a mapping workflow) must still have its parameters snapshotted.
2. **A run without `/pose`** (no SLAM) must give a report that says so plainly, not a stack trace.
3. **`tegrastats` missing or failing:** the run must still record, with a logged warning and no crash.
4. **An exact replay of a run whose `/scan` was dropped by the recorder itself:** detect the missing stamps and refuse, instead of silently replaying a different run.
5. **`imu_all:=true` with `imu:=false`:** refuse with a clear message.

### Task S1: Snapshot nodes that start late

**Files:** `src/race_diagnostics/race_diagnostics/snapshot_params.py` and its tests.

**Behaviour:**
- Keep watching the node list for the run's whole lifetime, polling every 2 s.
- Snapshot each node the first time it appears. Re-snapshot a node that restarts, as `<name>.<n>.yaml`.
- Live changes are already in the bag through `/parameter_events`.

**Tests:** the pure "which nodes are new" logic over successive node-list samples: a new node, a restart, and a vanished node.

### Task S2: System logs

**Files:** `src/race_diagnostics/launch/record_run.py`; a new ROS-free `src/race_diagnostics/race_diagnostics/system_log.py` with a small entry point.

**What it logs:**
- `<run>/system/tegrastats.log` from `tegrastats --interval 1000`. It runs without sudo on car 1 (checked 2026-10-26).
- `<run>/system/proc.jsonl`: 1 Hz CPU %, RSS and thread count per ROS node process, found by `__node:=` in `/proc/<pid>/cmdline`.

**Failure handling:** each logger failing to start is logged and the run continues (Review Focus 3).

**Tests:**
- The `/proc` parse on a fake `/proc` tree (CPU % from two `stat` samples, with a closed-form expectation).
- A missing `tegrastats` binary gives a warning, not an exception.

### Task S3: Package versions

**Files:** `src/race_diagnostics/race_diagnostics/run_metadata.py`.

**What it adds:** `metadata/packages.txt` listing `dpkg-query -W 'ros-jazzy-*'` versions, slam_toolbox first. Git state can't cover apt packages.

**Tests:** parsing of the `dpkg-query` output, and its absence handled.

### Task S4: Exact replay

**Files:** `tools/run_analysis/slam_replay.py`, plus a small rclpy feeder script beside it.

**`--exact` mode:**
- Runs `sync_slam_toolbox_node`.
- Feeds only the `/scan` messages whose stamps equal the recorded `/pose` stamps. That's the processed-scan record: 315 `/pose` against 314 SLAM updates on run `20261026-194913`.

**Tests:**
- The stamp-matching function, including a missing scan, which refuses (Review Focus 4).
- End to end: `--exact` on `20261026-194913` must reproduce the recorded `/pose` sequence to 1 mm and 0.1°. If it can't, report how close it gets and why. Don't loosen the bar silently.

**Also fold in Part A's deferred minor:** when slam_toolbox's map saver fails, write `map.pgm` and `map.yaml` from the replay bag's last `/map` (as was done for the cleaned 19:45 map) and set `map_saved: from_bag`.

### Task S5: `slam_report.py`

**Files:** `tools/run_analysis/slam_report.py`, tests.

**Report contents:**
- **Setup:** the odometry frame SLAM used (from the parameter snapshot), speeds and distance.
- **Heading drift** of `/odom`, `/odom/imu` and SLAM against each other: final value, maximum, and per-second RMS. This is the 2026-10-26 analysis made permanent.
- **Corrections and loop closures,** from `slam_metrics`.
- **Laps:** per-lap closure distance, heading error, corrections and quality verdict, from `race_diagnostics.run_events` log parsing.
- **Map consistency:** the share of scan endpoints within one cell of an occupied cell of the final map, per lap. It must be tested with a synthetic map and scans at a known offset (closed form).
- **Scan drops** ("queue is full") on a timeline against slam_toolbox's CPU % from S2.
- **Wheel distance against scan-matched distance.**

**Output:** `slam_report.txt`, `summary.json` and PNGs. `--compare runA runB` gives side-by-side numbers and overlays.

**Tests:** every metric against synthetic runs with closed-form answers, plus the Review Focus 2 case.

### Task S6: `map_course` runs the reports, and caps mapping speed

**Files:** `src/racerbot_launch/scripts/map_course`, `src/racerbot_launch/launch/map_course_launch.py`, tests.

**Changes:**
- After the launch exits, the wrapper runs `summarize_run`, `imu_report` and `slam_report` on the run folder and prints the headline lines. `analysis:=false` skips them; the wrapper strips that argument before the launch.
- **Mapping speed.** Since Part A, `gap_follow.yaml` ships `max_speed: 5.0`, and `map_course` maps on the same YAML. The gyro SLAM profile (`slam_gyro.yaml`) was validated by replay only up to about 3.3 m/s.
  - Make `map_course`'s `mapping_max_speed` default **3.5**, with a comment citing that.
  - Lift it only after a recorded gyro run at a higher speed gives a clean `slam_report`. This is map quality, not race pace.
  - The test checks the default and that an explicit value overrides it.

### Task S7: `imu_lap_turns` and `imu_all` (B2)

**Files:** `src/racerbot_launch/launch/map_course_launch.py`, `test/test_map_course_imu.py`, `docs/launchstart.md`.

**Behaviour:**
- `imu_lap_turns:=true` sets `auto_map_race_node` `odom_frame: odom_imu`, so the lap counter's turning comes from the gyro. It refuses without `gyro_odom:=true`, and the lap counter's frame must equal `vehicle_state.yaml`'s `imu_odom_frame`.
- `imu_all:=true` turns on `gyro_odom`, `imu_lap_turns` and `fused_speed`; an explicit `false` overrides it.
- Everything refuses with `imu:=false` (Review Focus 5).

**Tests:** in the existing `_wired_context` style, with `pytest.raises(RuntimeError, match=...)` for every refusal.
